# Prospective V2 Benchmark Contract

V2 must be preregistered before any new final labels are opened. It does not replace or modify v1.

## Payment amounts

Every request records distinct integer-paise fields for claimed refund amount, gateway-authorized execution amount, original captured amount, previously refunded amount, active reservation amount, and captured remaining balance. Every balance has an authoritative source and UTC as-of timestamp.

## Population boundary

Invalid ownership, currency, captured-state, and balance cases belong to deterministic integrity testing. Primary ML development and evaluation uses gateway-valid ambiguous claims. Deterministic invalid cases remain in a separate systems-safety report and are not attributed to model performance or adaptive-policy value.

## Shortcut controls

No simulated label may be derived directly from a model feature that exposes the target. Amount-to-paid ratio remains available to deterministic validation but is excluded from the ambiguous-claim model unless preregistered evidence establishes a non-trivial prediction purpose. Single-feature trees, feature permutation, subgroup removal, and scenario-blind reviews are release gates.

## Freeze protocol

Scenario mixtures, prevalence, seeds, split dates, feature schema, model candidates, calibration method, costs, and policy constraints freeze before the new final period is opened. V2 must use previously unused chronologically later cases and preserve v1 and v2 as separate immutable result versions.
